# 이슈 1

제목: [FEAT-13] 할 일 정보를 한 번에 수정하기

## 목적

할 일의 제목, 폴더, 중요·즉시 표시, 계획 날짜를 각각 다른 곳에서 고쳐야 했습니다. 폴더를 바꾸는 방법은 아예 없었고 계획 날짜를 옮기려면 지웠다가 다시 담아야 했습니다. 이 네 가지를 카드 메뉴의 수정하기 하나로 모읍니다.

- 작업 브랜치: `feature/task-plan-enhance`

## 작업 범위

- [ ] `PATCH /api/tasks/{taskId}/info` 신설. 제목·폴더·중요·즉시·계획 날짜를 한 트랜잭션에서 반영한다
- [ ] 계획 항목 id가 있으면 다른 날짜로 옮기고 없으면 그 날짜 계획에 담는다
- [ ] `PATCH /api/tasks/{taskId}/priority`, `/urgent`를 deprecated로 표시한다
- [ ] 데일리 플래너·폴더 목록·매트릭스 세 화면에 수정 모달을 붙인다
- [ ] 매트릭스에서는 중요·즉시를 잠근다. 두 값이 곧 사분면이라 여기서 바꾸면 카드가 보고 있던 구간에서 사라진다
- [ ] 대상 날짜에 같은 할 일이 이미 있으면 거절한다

## 완료 조건

- [ ] 모달 한 번의 저장으로 네 가지가 함께 바뀐다
- [ ] 일부만 반영되고 나머지가 실패하는 중간 상태가 없다
- [ ] 한 화면에서 고친 값이 다른 화면에도 새로고침 없이 나타난다
- [ ] 백엔드 테스트와 프론트 빌드가 통과한다

## 제외 범위

- 계획 날짜를 task의 컬럼으로 흡수하는 구조 변경. `docs/backlog/task-owns-plan-date.md`에 따로 적었다

# 이슈 2

제목: [FEAT-14] 계획과 할 일의 상태 소유 정리

## 목적

핀보드에서 메모를 할 일로 정리해 계획에 연결해도 옆의 데일리 플래너에 나타나지 않았습니다. 서버에는 저장되는데 화면만 모르는 상태였습니다. 같은 데이터를 세 화면이 각자 들고 각자 고치면서 서로를 모르는 구조가 원인입니다.

- 관련 문서: `docs/enhance/0903_계획_데이터_소유_구조_검토.md`
- 작업 브랜치: `feature/task-plan-enhance`

## 작업 범위

- [ ] `store/dailyPlanStore`가 날짜별 계획 항목을 소유한다
- [ ] `store/taskStore`가 할 일의 제목·상태·중요·즉시를 소유한다
- [ ] 화면마다 흩어져 있던 `taskOverrides` 세 벌을 없앤다
- [ ] 계획 응답에 실려 온 할 일 정보로 캐시를 채운다
- [ ] 페이징된 목록(매트릭스)은 지역 갱신이 불가능하므로 재조회로 맞춘다
- [ ] 로그아웃 시 두 store를 비운다

## 완료 조건

- [ ] 메모를 정리해 계획에 연결하면 데일리 플래너에 새로고침 없이 나타난다
- [ ] 메모에서 할 일을 만들면 매트릭스와 폴더 목록에 새로고침 없이 나타난다
- [ ] 매트릭스에서 세션을 시작한 뒤 플래너로 전환하면 오늘 항목에 그 할 일이 있다
- [ ] 한 화면에서 제목을 고치면 나머지 화면에도 같은 제목이 보인다
- [ ] 달을 옮겼다 돌아와도 이미 받은 달을 다시 조회하지 않는다
- [ ] 로그아웃 후 다른 계정으로 로그인하면 이전 계정의 데이터가 보이지 않는다

## 제외 범위

- 순서 변경 기능 복원

# 이슈 3

제목: [FEAT-15] 할 일 목록의 조회 조건 정리

## 목적

폴더 페이지는 전체와 미분류가 별도 화면이었고 정렬은 고를 수 없었습니다. 매트릭스는 상태로 좁힐 방법이 없었습니다. 조회 조건을 서버 파라미터로 옮기고 화면에서는 필터와 정렬로 다룹니다.

- 작업 브랜치: `feature/task-plan-enhance`

## 작업 범위

- [ ] `GET /api/tasks`의 `mode` 파라미터를 `sort`(desc·asc)로 교체한다
- [ ] `GET /api/tasks/matrix`에 `status` 파라미터를 넣는다. 커서 앞에서 걸러야 페이지네이션이 성립한다
- [ ] 폴더 페이지의 전체·미분류 화면을 하나로 합치고 미분류를 필터 조건으로 옮긴다
- [ ] 정렬은 필터와 다른 버튼으로 두고 두 버튼을 오른쪽에 묶는다
- [ ] 매트릭스 필터를 캘린더·매트릭스 토글과 같은 층위에 둔다
- [ ] 데일리 플랜 조회 정렬에 최신순을 넣는다

## 완료 조건

- [ ] 정렬을 바꾸면 서버에서 다시 받아 순서가 반영된다
- [ ] 상태 필터를 켜도 매트릭스의 무한 스크롤이 그대로 동작한다
- [ ] 잘못된 정렬·상태 값은 400과 ProblemDetail로 거절한다
- [ ] 백엔드 테스트와 프론트 빌드가 통과한다

## 제외 범위

- 매트릭스의 계획 기간 필터. `docs/enhance/0903_계획_데이터_소유_구조_검토.md` 8절에 설계만 적었다

# PR

제목: feat: 할 일 정보 수정과 계획 상태 소유 구조 정리

## 개요

할 일 하나를 고치는 데 필요한 동작이 화면마다 흩어져 있었고, 계획 데이터를 세 화면이 각자 들고 있어 한쪽 변경이 다른 쪽에 닿지 않았습니다. 수정 경로를 모달 하나로 모으고 계획과 할 일의 소유를 store로 끌어올렸습니다. 겸사겸사 목록 조회 조건도 서버 파라미터로 정리했습니다.

## 관련 이슈

- Closes #

## Feature

### 할 일 정보 수정

- 사용자 동작: 카드 메뉴의 수정하기에서 제목·날짜·폴더·중요·즉시를 한 번에 고칩니다
- Frontend: `TaskInfoModal` 신설. 데일리 플래너·폴더 목록·매트릭스에 연결했고 매트릭스는 중요·즉시를 잠급니다
- Backend: `TaskUseCase.updateInfo`가 한 트랜잭션에서 처리합니다. 매트릭스 rank는 중요·즉시가 실제로 바뀔 때만 새로 계산합니다
- API·DB: `PATCH /api/tasks/{taskId}/info` 신설. 응답은 갱신된 할 일과 바뀐 날짜의 계획입니다. 스키마 변경은 없습니다
- 검증: 유스케이스·서비스·컨트롤러 테스트 10건

### 계획과 할 일 상태 소유 정리

- 사용자 동작: 어느 화면에서 담거나 고쳐도 다른 화면에 곧바로 반영됩니다
- Frontend: `dailyPlanStore`·`taskStore` 신설. 화면마다 있던 `taskOverrides` 세 벌과 변경 후 재조회를 없앴습니다
- Backend: 메모 정리 확정 응답에 상태·중요·즉시를 실어 전체 재조회 없이 캐시를 채우게 했습니다
- API·DB: 스키마 변경 없음
- 검증: 프론트 빌드, 메모 정리에서 계획 연결까지의 흐름

### 할 일 목록 조회 조건

- 사용자 동작: 폴더 페이지에서 미분류와 정렬을 필터·정렬 버튼으로 고릅니다. 매트릭스는 상태로 좁힙니다
- Frontend: 전체·미분류 화면을 하나로 합치고 필터를 공통 컴포넌트로 재사용했습니다
- Backend: `GET /api/tasks`의 `mode`를 `sort`로 교체, `GET /api/tasks/matrix`에 `status` 추가
- API·DB: `mode` 파라미터와 `TaskListMode`를 제거했습니다. 미분류 조회 경로도 함께 지웠습니다
- 검증: 컨트롤러·유스케이스·서비스 테스트

## Fix

- 세션 시작 시 `plannedDurationSec`에 한 구간 길이를 보내 `INVALID_SESSION_DURATION`이 나던 문제. 휴식을 포함한 전체 길이를 보냅니다. 반복 기본값이 2회라 사실상 항상 실패하던 상태였습니다
- 계획한 시간을 넘기면 타이머가 00:00에 멈췄습니다. 이제 추가로 진행한 시간을 셉니다
- `NoteCard`의 타입 import 누락으로 깨져 있던 빌드를 고쳤습니다

## Refactor

- 날짜 문자열 헬퍼를 `lib/date`로 모았습니다. 네 곳에 복제돼 있었습니다
- 계획 항목과 할 일, 폴더를 합치는 join을 `features/plans/planItems`로 뺐습니다
- 개인 세션 시작 시 할 일을 진행중으로 바꾸던 처리를 제거했습니다

## 공통 변경

- 공통 UI·스타일: 매트릭스 카드에 그림자를 넣고 `--shadow-card` 토큰을 추가했습니다. 다이브 세션 피드에서 할 일 개수에 올리면 제목과 폴더가 보입니다
- 문서·인프라: `docs/backlog/task-owns-plan-date.md`에 계획 날짜를 할 일 컬럼으로 흡수하는 후속 안을 적었습니다

## 제외 범위

- 계획 날짜를 할 일의 컬럼으로 흡수하는 구조 변경
- 매트릭스의 계획 기간 필터
- 순서 변경 기능 복원
