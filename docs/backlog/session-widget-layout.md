# 세션 위젯 설정과 자유 배치

## 배경

F06과 F07의 세션 진행 화면은 제품이 정한 고정 배치를 사용한다. F07에서는 위젯과 음악을 현재 세션에서 조작하지만 사용자별 설정 저장, 재진입 시 복원, 자유 배치와 위치 저장은 후속 기능으로 분리한다.

## 위젯 설정 저장과 복원

위젯 설정은 세션 자체의 공유 상태가 아니라 사용자 개인 설정이다. 개인 세션과 이후 그룹 세션에서 같은 모델을 사용할 수 있도록 `(sessionId, userId)`를 식별자로 사용한다.

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| sessionId | Long | 설정이 속한 세션 |
| placeWidgetVisible | boolean | 공간 위젯 표시 여부 |
| taskWidgetVisible | boolean | Task 위젯 표시 여부 |
| timerWidgetVisible | boolean | 타이머 위젯 표시 여부 |
| participantWidgetVisible | boolean | 참여자 위젯 표시 여부 |
| musicWidgetVisible | boolean | 음악 위젯 표시 여부 |
| focusModeEnabled | boolean | 앱 내부 집중 모드 활성 여부 |
| musicVolume | decimal | `0.0`부터 `1.0` 사이의 개인 볼륨 |
| musicMuted | boolean | 음소거 여부 |
| musicPlaying | boolean | 마지막으로 저장된 재생 의도 |
| musicPlaybackPositionSec | integer | 마지막으로 저장된 재생 위치 |
| updatedAt | instant | 마지막 설정 저장 시각 |

### API 초안

```http
GET /api/sessions/{sessionId}/widget-settings
PUT /api/sessions/{sessionId}/widget-settings
```

- 개인 세션 시작 시 해당 세션과 사용자에 대한 기본 설정을 한 번 생성한다.
- 조회는 진행 중인 세션과 종료된 세션 모두 허용한다.
- 수정은 진행 중인 본인의 세션 설정에만 허용한다.
- 요청은 특정 시점의 전체 설정 DTO이며 누락된 필드를 기존 값으로 추정하지 않는다.
- 세션 소유자 또는 그룹 세션 참가자가 아니면 존재 여부를 노출하지 않고 `SESSION_NOT_FOUND` ProblemDetail을 반환한다.
- `musicVolume`은 `0.0`부터 `1.0`, `musicPlaybackPositionSec`은 0 이상이어야 한다.
- 음악 URL 자체는 F07에서 세션의 `music_url`로 저장하며 Widget Settings에 중복 저장하지 않는다.

### 저장 시점

- 위젯 표시 여부와 집중 모드가 변경될 때 전체 설정을 저장한다.
- 음악의 재생 위치는 매초 저장하지 않는다.
- 재생·일시정지, 탐색, 볼륨·음소거 변경과 페이지 이탈 같은 상태 전환 시점에 저장한다.
- 저장된 `musicPlaying`은 재생 의도를 나타낼 뿐 브라우저 자동재생 정책을 우회하지 않는다. 복원 후 필요한 경우 사용자의 재생 조작을 다시 받는다.
- 종료된 세션의 설정은 기록과 함께 유지하고 조회할 수 있지만 더 이상 변경할 수 없다.

### 결정 필요 사항

- 빠르게 연속된 전체 DTO 저장 요청의 순서와 충돌을 처리하는 방식
- 페이지 이탈 시 인증을 유지하면서 마지막 상태를 안정적으로 저장하는 방식
- 세션별 설정 외에 사용자 기본 설정을 별도로 제공할지
- 그룹 세션에서 개인 설정과 룸 공통 상태의 경계를 어디까지 둘지

## 위젯 자유 배치와 위치 저장

## 문제

- 사용자가 위젯을 이동할 수 있게 하면 타이머와 세션 종료 조작이 다른 위젯 또는 화면 밖에 가려질 수 있다.
- 픽셀 좌표를 그대로 저장하면 화면 크기, 확대 비율, 기기 방향이 달라졌을 때 같은 배치를 복원하기 어렵다.
- 드래그 조작만 제공하면 키보드와 보조 기술 사용자가 같은 기능을 이용할 수 없다.
- 개인 세션과 그룹 세션이 같은 위젯 설정 모델을 사용할 때, 세션별 배치와 사용자 기본 배치 중 어느 값을 우선할지 정해야 한다.
- 위젯의 접힘·표시 상태와 위치를 함께 저장하면 변경 충돌과 저장 시점을 일관되게 처리해야 한다.

## 권장 방향

자유 좌표 저장보다 제한된 레이아웃 슬롯을 우선 검토한다.

```text
top-left
top-right
bottom-left
bottom-right
```

- 위젯을 슬롯 사이에서 이동하고 한 슬롯 안의 순서를 저장한다.
- 타이머와 세션 종료 조작은 항상 접근 가능한 안전 영역을 보장한다.
- 화면이 좁아지면 저장된 데스크톱 배치를 모바일 순서로 변환하고, 화면이 다시 넓어지면 원래 슬롯 배치를 복원한다.
- 드래그와 동일한 결과를 만드는 키보드 이동 조작을 제공한다.
- 위치 변경은 드래그가 끝나거나 키보드 이동이 확정되는 상태 전환 시점에 저장한다.
- 배치 필드는 기존 전체 위젯 설정 DTO에 포함할지, 별도 레이아웃 DTO와 API로 분리할지 구현 전에 결정한다.

## 완료 조건 초안

- 사용자는 허용된 영역 안에서 개별 위젯의 위치 또는 순서를 바꿀 수 있다.
- 저장한 배치는 같은 사용자가 세션에 다시 진입했을 때 복원된다.
- 다른 사용자의 배치에는 영향을 주지 않는다.
- 화면 크기와 확대 비율이 달라져도 위젯, 타이머와 종료 조작이 화면 밖으로 사라지거나 서로 완전히 가려지지 않는다.
- 키보드만으로 위젯 이동과 순서 변경을 수행할 수 있고 현재 위치를 확인할 수 있다.
- 종료된 세션의 배치는 조회할 수 있지만 변경할 수 없다.

## 배치 관련 결정 필요 사항

- 자유 좌표, 제한된 슬롯, 사전 정의 레이아웃 프리셋 중 어떤 모델을 사용할지
- 배치를 세션별로 저장할지, 사용자 기본값도 함께 제공할지
- 개인 세션과 그룹 세션에서 같은 배치 규칙을 사용할지
- 위젯이 같은 슬롯을 선택했을 때 자동 정렬 또는 자리 교환 규칙
- 모바일에서 별도 순서를 저장할지, 데스크톱 배치로부터 파생할지
- 기존 Widget Settings API에 포함할지 별도 API로 분리할지

## 현재 범위

이 문서는 후속 설계와 구현을 위한 백로그다. F07에서는 F06의 고정 배치를 그대로 유지하며 사용자별 Widget Settings API, 설정 복원, 위젯 위치·순서·좌표 변경을 구현하지 않는다.
