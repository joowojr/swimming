## 개요

할 일 오거나이저가 화면과 무관하게 모든 폴더를 컨텍스트로 넣었다. 이를 **노트가 속한 범위만 참조**하도록 바꿨다. 그 과정에서 프롬프트를 설정으로 교체할 수 있게 저장소로 추상화하고 provider 별로 흩어져 있던 LLM 옵션을 정리했다.

프론트에서는 여러 화면이 각자 조회하던 공간 카탈로그를 store 하나로 모았다.

## Feature

### 기능 범위에 따른 오거나이저 컨텍스트 축소

- 사용자 동작: 폴더 상세에서 노트를 정리하면 그 폴더의 제안만 나온다. 세션 중에는 세션에 담긴 task 의 폴더만 참조한다.
- Frontend: `NoteCard` 가 노트의 범위(`contextType`, `contextId`)를 `TaskOrganizerPanel` 로 넘기고, 패널이 preview 요청에 실어 보낸다.
- Backend: `TaskOrganizerUseCase` 가 범위별로 폴더를 정한다. `SESSION` 은 `SessionService.getTaskIds` → `TaskService.getFolderIds` 두 단계로 푼다. `session_tasks` 를 아는 코드는 session 도메인 안에만 두어 `folder → task → session` 단방향 의존을 지켰다.
- API·DB: `POST /api/task-organizer/preview` 요청에 `contextType`, `contextId` 추가. 둘 다 선택값이라 **기존 호출은 그대로 동작**한다. `TaskRepository` 에 폴더 한정 컨텍스트 조회와 task→folderId 조회 추가.
- 검증: 범위별 폴더 조회, 소유권 검증, `contextId` 누락·불일치 400, 참조할 폴더 없음 400 — 모두 LLM 호출 전에 차단되는지 단위 테스트로 확인.

### 범위별 프롬프트 분리

- 사용자 동작: 폴더가 정해진 상태에서는 "이 메모에서 할 일 뽑기"만 수행한다. 폴더 적합성을 다시 따지지 않는다.
- Backend: `PromptKey.TASK_ORGANIZER`(분류) / `TASK_EXTRACTOR`(추출) 두 프롬프트. 추출 경로는 `folderId` 가 없는 별도 결과 DTO(`TaskExtractResult`)를 쓰고, 응답 매핑에서 컨텍스트 폴더로 확정한다.
- API·DB: 응답 계약(`TaskOrganizeResponse`) 변경 없음.
- 검증: 조립된 분류 프롬프트가 분해 전 원문과 **글자 단위로 동일**한지 대조하는 테스트를 뒀다. 조각으로 나누며 내용이 바뀌지 않았음을 보장한다.

## Refactor

- **프롬프트 저장소화** — 상수로 박혀 있던 경로를 `PromptRepository` + 설정으로 옮겼다. `classpath:` 와 `file:` 을 같은 속성으로 처리하므로, 나중에 이미지를 다시 만들지 않고 프롬프트만 교체할 수 있다. 기동 시 한 번 읽고 조립해 **경로 오타나 조각 누락이 첫 LLM 호출이 아니라 기동에서** 드러난다.
- **프롬프트 조각 공유** — 두 프롬프트가 공통 규칙(문장 분리·병합 9줄, 제목 작성 6줄)을 `&lt;!-- fragment: 이름 --&gt;` 마커로 공유한다. HTML 주석이라 마크다운에 렌더링되지 않고 본문의 백틱·XML 태그·중괄호와 충돌하지 않는다. 템플릿 엔진을 들이지 않은 이유는 변수 치환이 아니라 조각 삽입이 필요해서다.
- **LLM 옵션 추상화** — `ChatOptionsFactory` 를 provider 별로 나눴다(OpenAI / Ollama / OpenAI 호환). reasoning 모델은 `maxCompletionTokens` 를, 일반 모델은 `maxTokens`·`temperature` 를 쓰는 차이를 팩토리 안에 가뒀다. 프로필이 `llm/*.yml` 조각 하나를 `spring.config.import` 로 끌어다 쓰고 그 파일이 유일한 출처가 된다.
- **토큰 사용량 로깅** — 호출마다 프롬프트 키·토큰·입력 글자 수를 한 줄로 남긴다. 프롬프트를 바꿨을 때 변화를 그 프롬프트에 귀속시키기 위해서다.
- **place store 도입** — 홈 위젯·세션 생성 모달·세션 화면이 각자 조회하던 공간 목록을 zustand store 하나로 합쳤다. 카탈로그는 세션 중에 바뀌지 않는 정적 데이터라 한 번 채우면 다시 요청하지 않고 여러 화면이 동시에 `load()` 를 불러도 요청은 하나로 합친다.
- **place 응답에 asset key 추가** — 배경 에셋의 오브젝트 키를 함께 내려 프론트가 CDN URL 과 원본 키를 모두 다룰 수 있게 했다.

## 제외 범위

- **모델별 비교와 기본 모델 확정** — 평가는 `gpt-5.6-luna` 하나로만 돌렸다. 다른 모델과의 비교는 다루지 않는다.
- **분류 경로(`DEFAULT`·`SESSION`)의 프롬프트 평가** — 이번에 추가한 라벨 검증은 추출 경로에만 적용했다.
- **프롬프트를 이미지 밖 파일로 운영** (`file:` 경로) — 구조는 준비했으나 배포에는 적용하지 않았다.
- **세션 컨텍스트의 실사용 검증** — 그룹 세션 슬라이스에서 다룬다.
- 인프라(Terraform)와 배포 관련 변경은 이 브랜치에 포함하지 않았다.

## 프롬프트 평가

프롬프트는 컴파일러가 검사해 주지 않아 실행해서 재는 수밖에 없다. 추출 경로가 의도대로 도는지 확인하려고 `llmEval` 에 검증을 세 층으로 나눠 넣었다.

### 검증 층

| 층 | 방식 | 잡는 것 |
| --- | --- | --- |
| 구조 | 자동, 라벨 불필요 | `sourceText` 가 메모에 그대로 있는지, 한 원문이 두 바구니에 동시에 들어가지 않는지 |
| 라벨 | 자동, 시나리오당 라벨 2~5개 | `mustBeTask` 와 `mustBeUnclassified` 로 배정 자체를 양방향 검증 |
| 리포트 | 사람이 읽음 | 실행별 입출력·토큰·지연을 JSON 으로 남긴다 |

라벨을 양방향으로 둔 이유는 한쪽만 있으면 "전부 한 바구니에 넣기"로 통과할 수 있어서다.

### 시나리오

폴더는 셋 다 하나만 준다.

| id | 메모 구성 | 보는 것 |
| --- | --- | --- |
| `extract-unrelated-item` | 폴더 주제와 무관한 행동 1건 | 유일한 항목이 무관할 때 버려지지 않는지 |
| `extract-on-off-topic-mix` | 유관 행동 2건 + 무관 행동 2건, **전부 행동** | "행동인가" 축을 없애 주제 축만 남긴다 |
| `extract-actions-vs-thoughts` | 행동 2건 + 감상·막연한 생각 3건 | 비행동이 Task 로 새는지 |

### 반복 실행

`reasoning-effort` 를 쓰면 reasoning 모델이라 `temperature: 0.0` 이 전달되지 않는다. 같은 프롬프트로도 실행마다 결과가 달라 1회 실행은 게이트가 될 수 없다. 그래서 시나리오마다 `EXTRACT_RUNS = 5` 회 돌리고 통과율 `0.8` 이상을 요구한다.

초기 구성에서 2회차가 전부 통과했다가 같은 프롬프트의 3회차가 실패했다. 표본 하나로 판단하면 안 된다는 것을 그 자리에서 확인했다.

### `notActionable` → `unclassified` 개명 결과

바구니 이름만 바꾸고 프롬프트 문장은 그대로 둔 채 각각 15회씩 돌렸다.

| | 빈 응답 | 무관한 행동 | 실행 간 변동 |
| --- | --- | --- | --- |
| `notActionable` | 3/5 | 불규칙하게 유실 | 큼 |
| `unclassified` | **0/15** | **행동으로 인식해 보존** | **없음** |

두 가지가 달라졌다.

**빈 응답이 사라졌다.** `notActionable` 일 때는 한 줄짜리 메모에 두 바구니가 모두 빈 응답이 나왔다. 통신도 스키마 검증도 정상인데 내용만 비어서, 사용자에게는 메모가 사라진 것처럼 보인다. 오분류는 미분류 목록에 남아 사용자가 직접 옮길 수 있지만 빈 응답은 복구할 방법이 없다. `unclassified` 는 갈 곳이 생기니 버리지 않는다.

**무관한 행동을 Task 로 인식한 채 보존한다.** 폴더 밖의 행동도 행동으로 판정해 행동형 제목을 붙이고 `unclassified` 에 담는다. 비행동은 명사구 제목이라 미분류 목록에서 둘이 구분된다.

부수적으로 필드명이 프롬프트 본문보다 강하다는 것도 확인했다. 개명 전 본문에는 주제를 이유로 걸러내지 말라는 문장이 여러 개 있었지만 필드명 하나가 그것을 전부 눌렀다.
